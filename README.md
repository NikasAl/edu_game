# Edu Game — учебник как игра

Прототип обучающей системы, которая перекладывает произвольные учебные материалы
(учебники, статьи, конспекты) в игровой процесс: карта знаний, атомы идей,
испытания, видимый прогресс и «продолжить с места остановки» — как в игре.

Идея: игра живёт не в украшательствах (очки, бейджи, анимации), а в **структуре
прогрессии** — доступ к новому открывается через освоение старого, как в
metroidvania. Подробный дизайн-концепт см. в обсуждении проекта.

## Как это работает

### Ядро: атом идеи

Единица системы — не параграф, а **атом идеи**, удовлетворяющий трём критериям:

1. формулируется одним предложением;
2. иллюстрируется одним примером;
3. проверяется хотя бы одним автопроверяемым вопросом.

Атомы соединяются рёбрами двух типов:

- **hard** — без этой идеи понять нельзя (жёсткий гейт);
- **soft** — помогает, но не обязательна (узел доступен, но помечен «рискованно»).

### Игровой цикл

```
КАРТА (куда идти; рекомендация «золотого пути» всегда видна)
 → КАРТОЧКА ИДЕИ (одна формулировка + один пример + частая ошибка)
   → Испытание 1: ФЕЙНМАН — объясни своими словами (LLM-рубрика)
   → Испытание 2: ЗАДАЧИ — параметрические шаблоны, автопроверка без LLM
   → Испытание 3: СВОЯ ЗАДАЧА — придумай и проверь (LLM-валидация)
 → узел «освоен», карта перерисовывается, открываются новые узлы
 → автосейв после каждого шага; «Продолжить» возвращает точно на место
```

Гибридная прогрессия: золотой путь (топологический порядок hard-зависимостей)
жёсткий, боковые ветви можно проходить в любом порядке; вход в узел с
непокрытыми soft-зависимостями разрешён с предупреждением «рискованно».

### Дозированность

Один экран = одна идея. Всё остальное (зависимости, контекст) живёт на карте.
Анимации не входят в основной контур — только как опция-иллюстрация (в планах).

### Дерево карт

Карта — это контейнер связанных идей, а карты образуют дерево (`Material.parentId`):
внутри одной карты могут лежать другие карты. На графе дочерние карты видны как
узлы-порталы с прогрессом поддерева — клик открывает вход внутрь; вернуться наверх
можно по хлебным крошкам. Управление — отдельная вкладка «Карты» в нижней
навигации (кнопки «Карты» на «Главной» и на карте тоже ведут туда):
создать карту или подраздел, переименовать, переместить по дереву (защита от
перемещения внутрь своей ветви), удалить каскадом с подтверждением. Импорт создаёт
отдельную карту — в корень или внутрь выбранной. Так большой курс не превращается
в одну гигантскую простыню узлов, а тематическая связность сохраняется: каждая
подтема — свой мир со своим графом и прогрессом.

## Демо-курс

При первом запуске загружается курс **«Алгебра и начала анализа: Производная»**:
12 атомов в 3 регионах, гибридный граф зависимостей, 24 параметрические задачи
с машинно-проверяемыми ответами (решатели считаются безопасным интерпретатором
выражений, без `eval`). Весь цикл проходится без LLM: для фейнмановских
объяснений работает локальный демо-оценщик (эвристики), для «своих задач» —
честная самопроверка.

## LLM-операции

Подключается любой OpenAI-совместимый провайдер (Настройки → Добавить):
OpenAI, OpenRouter, DashScope/Qwen, локальные Ollama / llama.cpp / vLLM / LM Studio.

| Операция | Когда | Кэш |
|---|---|---|
| Разбор текста на атомы + граф зависимостей | ингест (редко) | в БД |
| Генерация параметрических задач + решателей | ингест (редко) | в БД |
| Проверка фейнмановского объяснения по рубрике | в игре | — |
| Проверка «своей задачи» (на тему? решаема?) | в игре | — |
| Подсказки уровня 1–3 | по запросу | — |

Самоверификация задач: LLM генерирует шаблон с решателем, значения параметров
рандомизируются при каждой попытке (защита от «запомнил ответ» и основа будущих
интервальных повторений).

## Отладка LLM

Каждый вызов модели журналируется, чтобы ошибки вроде «LLM вернул некорректный
JSON» были диагностируемыми:

- **Настройки → Журнал LLM** — последние 40 вызовов: полный промпт, сырой ответ
  модели, HTTP-статус, `finish_reason`, расход токенов, число попыток; кнопка
  «Копировать всё» отдаёт журнал целиком JSON-ом;
- **консоль браузера** (DevTools) — те же записи свёрнутыми группами `[LLM …]`;
- лимиты токенов подняты (4–20k): reasoning-модели (DeepSeek-R1, QwQ и т.п.)
  тратят `max_tokens` на «размышления» — при маленьком лимите ответ приходит
  пустым с `finish_reason=length`; клиент автоматически повторяет запрос
  с удвоенным лимитом;
- 429/5xx автоматически повторяются один раз через 2,5 с;
- `response_format: json_object` при отказе провайдера (HTTP 400) отбрасывается;
- извлечение JSON устойчиво к ```-обёрткам, тексту вокруг, `<think>`-блокам,
  сырым переводам строк внутри строк и обрыву ответа (см. `src/lib/llm-json.ts`).

## Архитектура

- **Next.js 16 + TypeScript**, один маршрут `/`, всё приложение — клиентское
  (локально-first, работает офлайн после загрузки).
- **Dexie (IndexedDB)** — локальная БД: материалы, регионы, узлы, рёбра, задачи,
  попытки, прогресс, провайдеры. Живые запросы (dexie-react-hooks) — прогресс
  на карте обновляется мгновенно.
- **Zustand** — UI-состояние (вкладки, тема, ингест-черновик).
- **@xyflow/react** — карта знаний: вертикальные слои по глубине
  hard-зависимостей, статусы узлов, жёсткие/мягкие рёбра.
- **Capacitor** — сборка APK; `NativeHttp`-плагин (паттерн NutriAdvisor) обходит
  CORS Android WebView для прямых вызовов LLM.
- Статус узла **вычисляется**, а не хранится: последняя попытка по каждому
  испытанию + гейты по рёбрам. Автосейв — запись попытки в IndexedDB.

## Запуск (веб)

```bash
npm install
npm run dev          # http://localhost:3000
```

## Сборка APK (Android)

Платформа `android/` теперь в репозитории (включая Java-плагин `NativeHttp` — HTTP через
Java в обход CORS WebView, без него LLM в APK не работает):

```bash
npm install
npm run build                # статическая сборка в out/
npx cap sync android         # копирует out/ + обновляет плагины
npm run apk:debug            # или: cd android && ./gradlew assembleDebug
```

Если у тебя уже был локальный `android/` (созданный ранее через `npx cap add android`) —
удали его и возьми из репозитория: в него добавлен собственный плагин HTTP и разрешения камеры.

## Импорт своих материалов

Вкладка «Импорт», три источника текста:

- **Текст** — вставка главы/статьи/конспекта (от ~500 знаков);
- **Ссылка (URL)** — загрузка веб-статьи: на Android через нативный HTTP
  (без CORS), в браузере при блокировке CORS — автоматически через
  reader-прокси; статья разбивается на разделы по заголовкам;
- **PDF** — два режима:
  - **Текстовый слой** — разделы создаются по пунктам оглавления (outline),
    без оглавления — по страницам; кириллица поддерживается (cMap/standard
    fonts лежат в `public/`). Быстро и без расходов, но в учебниках формулы
    и кодировка часто оказываются мусором;
  - **LLM OCR** — страницы показываются по группам оглавления, группы
    по умолчанию свёрнуты (большую книгу удобно листать списком разделов);
    развернув группу стрелкой, можно отметить отдельные страницы миниатюрами
    (ленивая отрисовка) и открыть крупный предпросмотр — страница отправляется в
    модель в высоком разрешении (~2200 px, render detail: high), иначе текст
    на сжатой картинке нечитаем. Распознаёт vision-модель (та же, что и
    «OCR с фото»): формулы переводятся в LaTeX, колонтитулы отбрасываются.
    Каждая страница — отдельный vision-запрос.
    Важно: в pdf.js v6 декодирование CCITT/JBIG2-сканов (типичные скан-книги)
    требует WASM-модулей — они лежат в `public/wasm/` и подключаются через
    `wasmUrl`; без них страницы сканов рендерятся белыми.

Для URL/PDF показывается список разделов с отметками и предпросмотром текста:
выбираешь нужное — выбранный текст собирается в поле импорта (можно
подредактировать). Дальше единый конвейер: LLM выделяет атомы, строит регионы
и граф зависимостей (циклы в hard-рёбрах автоматически понижаются до soft) →
ревью с правкой названий/формулировок → сохранение и генерация задач по каждому
атому. Материал становится отдельной картой (в корень или внутрь выбранной).

**Детализация идей**: длинный текст делится на фрагменты (размер зависит
от уровня: «Крупно» ~24 000 / «Обычный» ~10 000 / «Подробно» ~5 000 знаков),
идеи выделяются по каждому фрагменту отдельно и объединяются с дедупликацией —
иначе на больших текстах модель находит только ~десяток самых заметных идей.
На «Подробно» в ревью попадает заметно больше атомов (до 60).

Экспорт/импорт всего (материалы + прогресс + черновики + провайдеры) — в настройках.
На Android экспорт открывает системное меню «Поделиться» — файл можно отправить
в мессенджер и перенести на другое устройство; в браузере — обычное скачивание.
Импорт идёт порциями и оживляет даты: крупный бэкап не вешает WebView,
а после сбоя приложение само возвращается на главный экран (errorPath + 404-редирект).

## OCR с фото (передача письменного решения)

В узле у каждого текстового поля есть кнопка «Фото с решением»:
камера/галерея → обязательное выделение области с решением (рамка тянется
по фото или за угловые маркеры) → OCR через vision-модель → текст вставляется
в поле. Для поля ответа задачи есть короткий режим (только итоговый ответ).

По умолчанию OCR использует активного провайдера; если его модель не принимает
изображения — укажи отдельного провайдера/модель в «Настройки → OCR с фото»
(gpt-4o-mini, gemini-flash, qwen-vl-plus и т.п.). Тот же провайдер/модель
использует режим **LLM OCR** импорта PDF. Провайдера можно поправить
в любой момент: у карточки есть кнопка «Редактировать» (пустое поле ключа
= сохранить прежний).

## Локальные модели по HTTP (llama.cpp, Ollama, LM Studio)

Android по умолчанию запрещает открытие незащищённых http-соединений
(cleartext). В манифесте приложения включён `usesCleartextTraffic`, поэтому
локальные серверы в домашней сети работают напрямую: добавь провайдера
типа «llama.cpp server» с адресом вида `http://192.168.1.19:8080/v1`
(или Ollama `http://192.168.1.19:11434/v1`). Запросы идут через нативный
HTTP-плагин, минуя WebView.

## Черновики ответов

Всё набранное в узле (объяснение Фейнмана, ответы на задачи, своя задача)
сохраняется автоматически — в том числе неверные ответы и текст без отправки
на проверку. При повторном входе в узел поля восстанавливаются; если черновика
ещё нет — подставляется последняя отправленная попытка. Черновики входят
в экспорт/импорт.

```
                        ImportPanel (текст/URL/PDF + LLM OCR, детализация), SettingsPanel,
                        PhotoOcr (фото → кроп → OCR)
android/                Capacitor-платформа + NativeHttpPlugin.java
public/                 pdf.js worker, cmaps, standard_fonts, wasm (CCITT/JBIG2 для сканов)
```
